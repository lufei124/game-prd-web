# 独立项目迁移

本项目可以独立安装和运行，原 Skill 仓库只在一次性迁移时作为旧应用数据来源，运行时没有依赖。

## 安全顺序

1. 对比新旧应用代码，停止写入前核对运行任务和发布操作。
2. 停止旧服务，备份完整旧应用（含数据/会话）和待撤销的文档改动至两个项目之外的私有本地目录。备份不提交 Git。
3. 复制完整数据目录到新项目 `.data/`，逐文件核对复制校验值；启动 bootstrap 的事务升级。
4. 核验旧实体、版本、任务、审计记录与原文件均保留：

```bash
node --import tsx scripts/verify-data-migration.ts /备份/.data /新项目/.data
```

5. 在独立目录完成安装、构建、测试与启动，确保端口 4317 由新项目服务提供。
6. 成功后移走旧仓库本次新增的应用目录，仅撤销本次文档增量，保留其他改动。任一步失败时使用备份恢复旧服务，不提前清理。

## 数据兼容

数据库名称仍为 workbench.sqlite，HTTP API 和历史 ID 不变。首次升级添加通用内置 release，保留旧 release 的全部文件、历史任务快照和成果；用户编辑/导入扩展不变。单次升级记录为 migrations.version=2，重复启动不会再次修改资源或默认设置。

移除旧源仓库的默认授权，不扩大目录访问。旧资料来源路径仅作为溯源文字保留。新数据路径下会话继续归独立助手管理；旧版本会话记录原路径属于历史信息，新任务采用新目录。

数据、凭证、备份、node_modules 和测试产物均不提交 Git。独立仓库仅初始化，不自动提交或添加远端。

## 知识目录升级

停止写入并备份完整数据后启动新版。`KnowledgeTree.migrate()` 幂等补充知识 folderId：general 或未设置模块映射到根目录，其他旧项目模块建立同名目录；不会改写历史任务快照。验证时逐项比较原实体（忽略新 folderId）、检查原文件校验和及 SQLite 完整性。删除资料保留历史原文件，永久删除项目统一清理。

### 默认扩展 revision 2

停止旧实例写入后启动新版本。bootstrap 在开放 HTTP 和恢复任务之前，将数据目录（除已有 backups）复制到 `.data/backups/defaults-v2-时间戳/`，SQLite 使用 VACUUM INTO 生成一致性副本，比对全部实体行并运行 integrity_check。事务开始时再次校验备份后实体未变化，否则中止升级。

升级只新增内置 release 和低保真风格，更新默认修订标记，逐条验证其他已有实体和历史 release 保持原值。用户改过的扩展不自动覆盖，原有绑定保留。备份留在受 Git 忽略的数据目录。回退也须停止写入并恢复完整备份，不能混用不同版本的数据库与文件。此次开发仅在临时目录验证升级，未主动迁移实际工作数据。
