# game-prd-web · 产品工作台

本地优先的产品需求工作台。核心流程不是“先填表”，而是从一段自然语言需求开始：Codex 自动检索项目知识，逐轮澄清关键决策，形成需求卡，再进入交互原型、PRD、可选 AI 评审和评审讲解。

技术栈：React + TypeScript、Node.js、SQLite、本地文件、OpenAI Codex SDK。

## 启动

需要 Node.js 24+ 和 npm：

```bash
npm ci
npm run build
npm start
```

打开 `http://127.0.0.1:4317/`。数据默认保存在项目根目录 `.data/`；可用 `WORKBENCH_DATA` 指定其他目录。服务只监听本机。

开发模式：

```bash
npm run dev
```

## 产品流程

### 1. 新建需求

项目首页只保留：

- 需求
- 知识库
- 设置

点击「新需求」后进入类似 Codex Desktop 的聊天界面。首屏不展示空需求卡、空原型面板或阶段配置，用户直接描述想做什么。

### 2. 自动检索项目知识

用户发送需求后，宿主自动使用当前项目知识进行检索，不要求用户先选择文件。

检索采用文档分块 + 标题/文件名/正文关键词混合评分，返回最相关文档及命中片段。同一资料源重复同步且内容未变化时不会创建重复版本。

需求也可以固定「重点资料」。重点资料始终进入本需求后续任务快照，同时仍保留全项目自动检索。

### 3. 需求澄清

需求阶段使用工作台内置的固定澄清流程，不需要选择 Skill。

逻辑参考 design tree / frontier：

1. 先把需求拆成决策树。
2. 能从知识库查到的事实由 AI 自己解决，不反问用户。
3. 每轮只询问当前已经具备前置条件的关键决策。
4. 每个问题附带推荐答案和简短理由。
5. 用户回答后重新计算下一轮问题，不重复已经确认的内容。
6. 关键内容逐渐完整后生成/更新需求卡草稿。
7. 没有关键隐含假设后等待用户点击「确认需求」。

需求卡形成后，右侧成果区才展开。

### 4. 交互原型

确认需求后自动进入原型阶段并生成第一版自包含 HTML。

原型支持两种修改方式：

- 直接在聊天中描述，例如“把购买按钮放到价格下面”。
- 点击原型中的具体 DOM 元素，再输入修改要求。

已有原型的 AI 修改不会直接覆盖正式版本：

`当前版本 → AI 候选 → 预览 → 应用修改 / 放弃`

只有用户点击「应用修改」后才创建新的正式原型版本。放弃候选不会改变当前原型。
应用与放弃都会写入 SQLite 的任务审计状态，刷新页面不会让已处理候选重新出现。需求卡、原型和 PRD 均可从历史版本恢复；恢复操作会创建一个新的当前版本，不覆盖历史记录。

修改需求后，相关原型和 PRD 会按照版本依赖重新检查；修改原型后，已有 PRD 会标记待同步。

### 5. PRD

确认原型后自动生成 PRD。

所有项目共用一套全局 PRD 模板。模板可在「设置」中直接编辑；模板修改只影响之后生成的 PRD，不覆盖历史文档。

PRD 支持：

- Web 直接编辑
- 对话修改
- Markdown 导出
- 历史版本
- 发布飞书

工作台内置 PRD 写作规则，要求关键业务规则使用稳定编号，验收标准可追溯，并明确异常、边界、数据、权限和依赖。

### 6. 可选多 Agent 评审

PRD 初稿完成后可以启动多 Agent 独立评审，也可以直接跳过。

默认角色：

- 产品
- 交互设计
- 研发测试

评审角色和关注点可以在 Web 设置中全局修改或增加，例如运营、数据、合规。

各评审角色读取同一份冻结 PRD，彼此不共享结论，也不能直接修改 PRD。评审结果统一输出问题列表：

- 问题
- 风险/严重程度
- 修改建议
- 来源角色

用户逐条选择：

- 采纳
- 不采纳
- 稍后处理

只有「采纳」的问题会交给主 Codex 统一修改 PRD。评审 Agent 不替用户做业务决策。

如果跳过 AI 评审，终稿确认记录会明确保存 `reviewStatus=skipped`；不会伪装成“评审通过”。

### 7. 可选需求评审讲解 HTML

PRD 后可以额外生成「需求评审讲解」。

它参考 Show Me 的表达原则，不是把 PRD 原样转换成网页，而是重新组织为更适合产品需求评审会议的 HTML，例如：

- 需求背景和目标
- 用户流程
- 核心页面与交互
- 关键规则
- 状态与异常
- 重点变更
- 评审关注项

讲解 HTML 可预览、导出，并可连续生成多个版本。它是附加成果，不影响 PRD 终稿状态。
讲解版本保存在 SQLite，并记录所依据的 PRD 版本；PRD 更新后，界面会提示旧讲解已过期，需要为当前 PRD 重新生成。

## 知识库

### 本地文件夹

在项目「知识库」中关联本地文件夹。首次关联会显式记录授权目录，之后可以「立即同步」。知识库页面打开期间还会周期性检查已关联资料源。

目录导入：

- 忽略隐藏文件、`node_modules`、`dist`、`history`
- 拒绝软链接
- 单次最多 600 个文件 / 20 MB
- 保留目录结构

### 飞书文档

知识库也可以关联飞书文档。工作台只读取文档用于解析和索引，不修改原始飞书内容。

### 支持格式

- Markdown
- TXT
- CSV
- PDF
- DOCX
- PNG/JPG/WebP/GIF 原图

扫描型 PDF 当前不自动 OCR；图片可以作为显式视觉参考，但不会被假装成已解析文本。

### 只读原则

知识源默认只读。AI 可以读取、引用和检索知识，但不能修改本地源文件或飞书原文。

## Codex

产品界面只支持 Codex，不再提供 Claude 选择和 Claude 配置。

默认配置：

- Codex
- `gpt-5.6-terra`
- 中等思考深度
- ChatGPT 订阅登录

在「设置」中可以修改默认模型和思考深度；需求输入框底部也可以针对本次任务临时调整模型和思考深度。

### ChatGPT 订阅登录

1. 启动工作台并进入「设置」。
2. 点击「使用 ChatGPT 登录」。
3. 打开官方设备登录页面并完成授权。

认证文件独立保存在 `.data/codex-auth/`。为避免订阅凭证刷新冲突，同一工作台一次只执行一个订阅 Codex 任务。

也可以显式改成 API Key 模式：

```dotenv
WORKBENCH_CODEX_AUTH_MODE=api-key
WORKBENCH_CODEX_API_KEY=你的独立_OpenAI_API_Key
WORKBENCH_CODEX_BINARY=/可选/自定义/codex
PORT=4317
```

API Key 与 ChatGPT 订阅额度独立计费。

### 复用本机 Codex Skills

工作台不再维护自己的 Skill 扩展中心。

每次任务启动时，会把本机 Codex Skills 目录只读复制到该任务隔离的 `CODEX_HOME/skills`。默认来源是：

```text
~/.codex/skills
```

也可以设置：

```dotenv
WORKBENCH_CODEX_SKILLS_DIR=/你的/Codex/skills
```

因此 Codex 可以继续发现用户本机已安装的指令型 Skills；用户也可以在聊天中明确要求使用某个 Skill。

为了保证产品数据隔离，工作台仍关闭 Shell、任意 MCP、其他项目目录和开放网络工具。依赖执行脚本、安装依赖或外部工具的 Skill 可能无法完整运行；此限制不会被 Skill 内容自行扩大。

## 固定阶段 Prompt 与旧扩展兼容

正常 Web 流程的阶段能力由工作台内置固定 Prompt 控制：

- 需求澄清
- 原型
- PRD
- 评审
- 评审讲解

用户不需要选择阶段 Skill，也不能通过聊天内容切换阶段或获得确认权限。

旧 Extension / Skill / Style 的数据库结构和直接任务 API 暂时保留，用于历史项目、迁移和测试兼容，但新版 Web 不再展示扩展中心，也不会在正常对话流程中自动选择这些资源。

全局 PRD 模板目前继续复用旧 release 存储作为底层版本容器，但在产品层只呈现为「PRD 模板」，不是扩展系统。

## 飞书交付

飞书发布继续使用独立安装的 `lark-cli` 和操作系统钥匙串：

```bash
lark-cli config init
lark-cli auth login
lark-cli auth check --scope "docx:document:readonly docx:document:create docx:document:write_only drive:file:upload" --json
```

发布必须由用户明确确认；远端冲突或未知创建结果不会静默覆盖。

## 数据与安全

- SQLite 是业务状态源。
- 原文件保存在 `.data/files/`。
- 版本、确认、任务、评审裁决和发布记录独立保存。
- HTTP 仅接受 loopback Host、同站 Cookie、Origin 与 CSRF。
- 原型 iframe 禁止联网、表单提交、外部对象和 same-origin 权限。
- Codex 每个任务使用隔离 HOME 和工作目录。
- Skills、知识资料、模型输出都不能扩大宿主权限。

本地优先不等于离线：发起 AI 任务时，本次需求、自动检索到的资料、重点资料及必要模板会发送给在线模型。
